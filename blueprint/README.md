# A draft Appendix H, generated from the Lean development

The appendix's own prose proofs are not machine-checked and are not the reliable artifact; the
Lean development is. So this draft is an account of **the development** — its statements
translated into English, its proofs sketched from what those proofs actually invoke, and its
bearing on the main text stated alongside. `app_doubling.tex` is not an input.

```
blueprint/
  exposition/                     THE ONLY HAND-EDITED DIRECTORY
    GFNBounds.Doubling.main_*.md    one per result: statement, relation, sketch
    _front.tex, _differences.tex    the framing sections
  src/content.tex                 GENERATED — do not edit
  appendix_H.tex                  GENERATED — the paper-ready fragment
  print/print.pdf                 build output (git-ignored) — 7 pages
  web/                            build output (git-ignored)
  superseded-appendixH/           the earlier draft, built the wrong way round
docs/
  lean-facts.json                 GENERATED by scripts/lean_facts.lean from the environment
  lean-graph.{dot,svg}            GENERATED — the verified dependency graph
```

## Build

```sh
make appendix        # extract, generate, lint, graph, pdf, web
```

Needs a current `lake build`, `pip install leanblueprint`, graphviz, and a TeX Live with
`lualatex`, `unicode-math` and `fontspec`.

## The three stages

**1. Extract.** `scripts/lean_facts.lean`, run through `lake env lean`, walks the compiled
environment and writes `docs/lean-facts.json`: for each of 1109 declarations its kind, module,
line, pretty-printed type, docstring, axioms, and the project constants its **proof term**
invokes, from `Expr.getUsedConstants`.

One trap is worth naming. `ConstantInfo.value?` withholds theorem values at this Lean version —
it answers `none` for a `thmInfo` whose proof is present — so the projection has to be written
out by hand. Getting it wrong is silent: every dependency set comes back empty and the graph
looks like a set of isolated theorems.

**2. Author.** One file per result under `exposition/`, with three sections — `statement`,
`relation`, `sketch` — and front matter recording the hash of the Lean type the text was
written against. Seed a new one with

```sh
python3 scripts/appendix.py --skeleton main_unbounded
```

which prints the Lean-derived draft: the substantive steps of the proof with the types the
author ascribed to them (`scripts/proof_skeleton.py` reads those from source and drops the ones
that only invoke arithmetic), then every named result the proof invokes with its own docstring.

**3. Emit.** `scripts/appendix.py` writes `src/content.tex`, `appendix_H.tex` and
`docs/lean-graph.dot`.

## The gates

This is the part that matters. `python3 scripts/appendix.py --lint` fails on:

1. **a stale statement** — the recorded type hash no longer matches, so the English describes a
   theorem that has since changed shape;
2. **an unsupported citation** — a sketch names a lemma that the proof does not invoke, to
   depth three;
3. **a silent omission** — the proof invokes a *theorem* the development names as a result, and
   no sketch mentions it;
4. **an unknown declaration** — a cited name is not in the environment;
5. **an axiom** — a result rests on something outside `propext`, `Classical.choice`,
   `Quot.sound`;
6. **register** — dates, bucket letters, source file names, and the rest of the certification
   vocabulary.

Gates 2 and 3 are why the phrase *derived from the Lean proof* is a checked property here
rather than a claim. All four of the first four have been confirmed to fire.

## Known limits

* The sketches are **authored**, not generated. What is mechanical is the evidence they are
  checked against; the English is written by hand and can still be wrong about *why* a step
  works, only not about *which* steps there are.
* Scope is the fifteen results assembled in `GFNBounds/Doubling/Main.lean`. The declarations
  beneath them are named in the sketches and counted in the closing table but are not
  themselves stated; `main_truncation_sqrtK` alone rests on 393 of them.
* The `leanblueprint` dependency graph is switched off. The fifteen results are siblings and
  none invokes another, so a graph over them alone would be fifteen isolated nodes; the real
  one, drawn from the environment, is `docs/lean-graph.svg`.
